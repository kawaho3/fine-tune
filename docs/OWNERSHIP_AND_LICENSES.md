# Ownership, Commercial Use, and Third-Party Licensing

## Intent

Create an independently branded, commercially operable product with original application code and a replaceable stack. Ownership of original code does **not** make third-party frameworks, models or their assets our intellectual property.

## Repository status

As of 13 November 2026 this repository is **public** and does **not** carry a project-wide LICENSE file. Public visibility does not grant unrestricted reuse or redistribution rights. Maintainers must decide on license and contribution terms before inviting substantial external source-code submissions or launching a commercial distribution.

## Dependency requirements

For each adopted upstream library/service/model record:
- Repository URL, exact release/commit, license and required notices.
- Copyright ownership and permitted commercial use.
- Runtime/service restrictions (including browser runtimes, trademarks, hosted APIs).
- Distribution, modifications, attribution and source-publication obligations.
- Optional modules with different licensing; assets, fonts, templates and datasets.
- Vulnerabilities, maintenance, provenance, and transitive dependency requirements.

Keep all required notices with shipped code and review copyleft/network-service licenses with qualified legal counsel if necessary. Do not assume a library is permissible merely because its source is on GitHub.

## Special watch items

- bolt.diy may involve separately governed WebContainers commercial runtime terms.
- Dyad core and optional pro components can have different licensing.
- Some tracing/training products include separately licensed enterprise or studio modules.
- Open-weight model licenses and training-data licenses differ from application code licenses.
- A public GitHub repository cannot keep trade secrets private; do not place credentials, confidential plans or private customer examples here.

All statements above are review flags, **not completed legal advice or final verified findings**.
