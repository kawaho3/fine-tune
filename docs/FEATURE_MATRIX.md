## Research protocol for competitors

For each competitor, record the date, direct product documentation or a reproducible trial, supported feature, constraints, price/usage terms, and screenshot or test evidence. Keep the competitor findings in a future evidence-backed benchmark table. Do not copy proprietary code, text, design assets, or branded UI.

## Differentiation metrics

Primary: end-to-end task completion on a held-out suite; build success; behavioral test pass rate; cost per successful project; time to live preview; regressions after follow-up edits. Secondary: accessibility, visual similarity to user-provided references, export portability, user satisfaction.

Feature parity is a multi-release goal, not a first-milestone acceptance criterion.
